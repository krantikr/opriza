# Free-tier deployment

Vercel (frontend) + Render (backend) + Neon (Postgres) + GitHub Actions (cron
email sync). None of it needs a paid plan.

The pieces have a dependency order: **Neon → Render → Vercel / GitHub secrets**,
because the Render URL does not exist until the service is created, and Vercel's
API rewrite points at it.

---

## 1. Neon — Postgres (you)

1. neon.tech → sign in → **New Project** (region near your users).
2. Open the project's **SQL Editor** and run this. The app **refuses to boot**
   as a superuser / BYPASSRLS role (tenant isolation is enforced by row-level
   security — see `app.core.tenancy.assert_rls_enforced`), so a dedicated
   NOSUPERUSER NOBYPASSRLS role is mandatory:

   ```sql
   CREATE ROLE steeldesk_app LOGIN PASSWORD '<pick-a-strong-password>'
     NOSUPERUSER NOBYPASSRLS NOCREATEDB NOCREATEROLE;
   GRANT CONNECT ON DATABASE neondb TO steeldesk_app;
   GRANT USAGE, CREATE ON SCHEMA public TO steeldesk_app;
   GRANT ALL ON ALL TABLES IN SCHEMA public TO steeldesk_app;
   GRANT ALL ON ALL SEQUENCES IN SCHEMA public TO steeldesk_app;
   ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON TABLES TO steeldesk_app;
   ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON SEQUENCES TO steeldesk_app;
   ```

3. Build the `DATABASE_URL` (note the `+psycopg` driver prefix and `sslmode`):

   ```
   postgresql+psycopg://steeldesk_app:<password>@<neon-host>/neondb?sslmode=require
   ```

   The `<neon-host>` is in Neon's connection panel (looks like
   `ep-xxxx-xxxx.<region>.aws.neon.tech`).

---

## 2. Render — backend (you)

1. render.com → **New → Blueprint** → connect GitHub → pick
   `SaurabhCegian/Sales-Quotation-Copilot`, branch **main**. It reads
   `render.yaml` and creates a free Docker web service.
2. Set these env vars in the dashboard (JWT_SECRET and CRON_SECRET are
   auto-generated by the blueprint; override CRON_SECRET with the value below
   so it matches GitHub):

   | Var | Value |
   |-----|-------|
   | `DATABASE_URL` | the Neon URL from step 1 |
   | `CREDENTIAL_KEY` | (generated — kept out of this file; paste the Fernet key) |
   | `CRON_SECRET` | (generated — paste; must match the GitHub secret) |
   | `OPENROUTER_API_KEY` | your OpenRouter key |
   | `CORS_ORIGINS` | the Vercel URL from step 3 (temporarily `*` until then) |

3. Deploy. First build is slow (installs WeasyPrint libs). When it's live, copy
   the service URL, e.g. `https://quotation-copilot-api.onrender.com`.
   Check `https://<url>/health` returns `{"status":"ok",...}`.

   > If the service logs "tenant isolation is not in force" and exits, the
   > DATABASE_URL role is still a superuser/BYPASSRLS role — redo the Neon role.

---

## 3. Vercel — frontend

1. `frontend/vercel.json` has an API rewrite with a placeholder host
   `REPLACE-WITH-RENDER-HOST`. Replace it with the Render host from step 2
   (host only, no `https://`, no trailing slash), commit, push.
2. Vercel project (root directory = `frontend`) linked to the repo auto-deploys
   on push. The rewrite sends `/api/*` to Render; everything else is the SPA.
3. Put the resulting Vercel URL into Render's `CORS_ORIGINS` and redeploy Render.

---

## 4. GitHub Actions — cron email sync

Repo → **Settings → Secrets and variables → Actions → New repository secret**:

| Secret | Value |
|--------|-------|
| `API_BASE_URL` | the Render URL, e.g. `https://quotation-copilot-api.onrender.com` |
| `CRON_SECRET` | same value as Render's `CRON_SECRET` |

The workflow (`.github/workflows/email-sync-cron.yml`) then POSTs to
`/api/v1/pipeline/cron` every ~5 min, which sweeps every active desk (each
checked on its own crawl window) and wakes the Render service if it was asleep.
Trigger it by hand once from the **Actions** tab (**Run workflow**) to confirm a
`202`.

> Scheduled workflows auto-disable after 60 days with no repo commits — a
> periodic commit keeps it alive.
